\section{The Cloud}


\begin{frame}{What is the cloud?}{Official definition by ISO}
  A paradigm for enabling network access to a scalable and elastic pool of shareable physical or virtual resources with self-service provisioning and administration on demand.

\begin{frame}{What is the cloud?}{My simplified definition}
  A computer or a specific computing service that we can access remotely over the internet.
  \begin{itemize}
    \item Usually, the hardware behind the cloud sits in \textbf{data centers}
    \item Technically, a cloud computer can be used for anything a personal computer can do, except for things that strictly require physical access to the hardware
    \item The hardware and part of the software are owned and managed by someone else; we are renting them, subject to specific terms
  \end{itemize}

\end{frame}


\begin{frame}{Why call it ``the cloud''?}
  \begin{itemize}
    \item Source: network diagrams, where a \textit{fluffy cloud symbol} is used to convey ``somewhere out there is the network, the details do not matter''
    \item The symbolic meaning of the cloud gradually shifted to represent ``computing resources at the other end of the internet''
  \end{itemize}

  IT companies rent out computing resources they accumulated to handle peak hours that are idle most of the time.

\begin{frame}{The cloud as a business model}
  \begin{block}{Benefits for us consumers}
    \begin{itemize}
      \item A new computer can be set up and ready to use within minutes
      \item Pay for what we use, mitigate the need for purchasing hardware up front
      \item We do not need to worry about the management of the hardware, network infrastructure, electricity, etc.
    \end{itemize}
  \end{block}

  \begin{block}{Downsides for us consumers}
    We never own the hardware and are subject to the cloud provider's pricing, terms, and conditions
  \end{block}
\note{
}
\end{frame}


\begin{frame}{Virtualization: The technology powering the cloud}
  \begin{itemize}
    \item Virtualization can slice a powerful computer's hardware (e.g., CPU cores, memory, hard drive) or computing resources in general (e.g., CPU core hours) into small pieces (virtual machines)
    \item Each virtual machine can have its own operating system and everything above, isolated from other virtual machines
  \end{itemize}
  This allows us to rent cloud computers that fit exactly into our needs.

\end{frame}


\begin{frame}{Virtualization vs. containerization}
  \begin{itemize}
    \item \textbf{Virtualization:} virtualizes the entire hardware, allowing each virtual machine to run its own operating system
    \item \textbf{Containerization:} all containers share the host computer's operating system's kernel
  \end{itemize}

\section{Public Endpoints}


\begin{frame}{Current status of our API endpoints}
  They are publicly reachable by clients over the internet, but not in a shape we want.

  \begin{itemize}
    \item \textbf{Raw IP address:} The endpoint is only reachable through our cloud computer's IP address
      \begin{itemize}
        \item An IP address is hard to remember and looks unprofessional
        \item An IP address cannot transfer to a new virtual machine if we ever need to migrate our service
      \end{itemize}
    \item \textbf{Unencrypted HTTP traffic:} The full content of the requests clients send to our API server, and the responses it sends back, is visible to anyone on the same network path
      \begin{itemize}
        \item A huge security loophole since the requests and responses might contain highly personal or confidential information
        \item Most modern clients and web browsers block unencrypted HTTP traffic altogether
      \end{itemize}
  \end{itemize}

  \vspace{1em}
  \textbf{Live demo:} The reading material (blog site) deployed on a cloud virtual machine.

}
\end{frame}
